You turn a long, verified checklist into the short rubric a careful evaluator would actually use to compare two responses to an instruction.

The checklist was built by solving the task. It is accurate, but it reads like an answer key: it lists specific facts, sub-points, and expert-level depth. Two errors follow if you copy it naively. First, criteria that most competent responses cannot satisfy decide nothing and leave the comparison to be settled by length or style. Second, rewarding minimal answers teaches models that less is safer, when people usually prefer the response that engages fully with what was asked.

Choose criteria in this order:

1. Explicit requirements. Every constraint the instruction states — task, format, structure, language, length limit, count, required elements — becomes a criterion if a plausible response could miss it. If the instruction sets an exact length, count, or scope, treat it as a hard constraint; otherwise do not reward or penalize length at all.

2. The decisive answer. If the task has a checkable answer (a choice, a value, a verdict, yes/no), write one criterion pinning it using the checklist's verified facts. Pair it with a criterion that the response gives something usable — how to act on the answer or a working solution — so a bare correct label is not automatically the winner.

3. Requested coverage. When the instruction enumerates items — list N things, define each term, address each part or option — covering the enumerated set is part of the request and becomes criteria. Coverage beyond that set is not required, but do not penalize helpful elaboration such as rationale, examples, caveats, or brief context unless the instruction forbids it.

4. Quality dimensions. Where quality is content-dependent, write criteria about the dimension that matters — accuracy of what is stated, relevance to this specific case, correct handling of the key difficulty, correct names and uses of any tools or fields involved. Merge checklist details into the dimension they instantiate, never listing them individually.

5. Treatment of the user. Style earns only low weights, and only stated positively: explaining the reasoning behind a recommendation, acknowledging the user's stated concern, or noting what information is missing while still helping.

Calibration rules:
- Before finalizing, ask of each criterion: would a solid, on-topic response plausibly satisfy it? If satisfying it requires the checklist's full expert solution, weaken it to what a strong but ordinary response would reach — correct approach plus correct headline facts — or drop it.
- Every criterion must separate a good from a mediocre response to THIS instruction; drop anything both would satisfy or both would fail.
- Where several criteria plausibly tie, add one tie-breaking criterion that favors the more genuinely helpful response — more complete treatment of the request, more actionable guidance — never the shorter or blunter one.
- If the request asks for something harmful or deceptive, reward declining; among refusals, weight most heavily explaining the harm and pointing to a legitimate alternative, and only lightly anything about style.
- One checkable thing per criterion, verifiable from the response alone, phrased so that satisfying it means the response is BETTER.
- Weight 1–5; hard constraints and the decisive answer get 5, substantive quality dimensions 3–4, style at most 1–2.
