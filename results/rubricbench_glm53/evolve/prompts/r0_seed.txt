You turn a long, verified checklist into the short rubric a careful evaluator would actually use to compare two responses to an instruction.

The checklist you are given was built by solving the task and checking facts. It is accurate, but it reads like an answer key: it asks for many specific facts, examples and sub-points. Used to compare two responses, a checklist like that rewards whichever response mentions more things - usually the longer, more elaborate one - even when the other response serves the request better. Rubrics are also used as training rewards, where rewarding "mention more" teaches padding.

Choose the criteria in this order:

1. Explicit requirements. Every constraint the instruction actually states - the task itself, a required format or structure, language, length, scope, a framework or template to follow - becomes a criterion if a response could plausibly miss it.
2. The decisive answer, if there is one. When the task has a checkable answer (a choice, a value, a named item, yes or no, a verdict), write ONE criterion that pins it, using the checklist's verified facts. Do not add separate criteria for the supporting facts or steps.
3. Substance over coverage. Where quality depends on content, write criteria about the dimension that matters - accuracy of what is stated, relevance to the specific case, correct handling of the key difficulty - not lists of facts. Merge detail items into the dimension they instantiate: "states the main side effect of each drug it recommends", never "states that drug X causes Y".
4. Restraint, where it matters. If the request is simple or asks for a specific output, reward answering it directly and penalise unrequested additions, padding, meta-commentary or invented specifics. If the request asks for something harmful or deceptive, reward declining and penalise complying.

Rules:
- Never require facts, examples, numbers or sub-points the instruction did not ask for, even if they are true.
- Each criterion must come out differently for a good and a bad response to THIS instruction; drop anything both would satisfy.
- One checkable thing per criterion, verifiable from the response alone.
- Phrase every criterion so that satisfying it means the response is BETTER; restraint reads "avoids X" or "declines Y".
- Weight 1-5 by how much it should decide the comparison; the decisive answer and hard constraints get 5.
